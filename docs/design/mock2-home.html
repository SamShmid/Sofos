1

Naming resolved: nav, page and workspace no longer collide

Today the sidebar's app-level link already says Overview (a partial fix), but HomePage.jsx still renders <h1>Home</h1> — while a real workspace is also named "Home." Three things, one word, no way to tell them apart in conversation. This mock changes only the page heading to Overview, matching the nav link that already agrees with it.

2

The workspace keeps its own name — "Home"

The default workspace is a real, distinct entity (every account gets one seeded on registration) and stays called Home, same as today. It just no longer has to share its name with the page it happens to sit on. Nothing about workspace naming or seeding changes.

3

The roll-up fix — this panel finally means something

Today SuggestionsPanel on this page is called with container={ superWorkspace } — i.e. only suggestions proposed directly at the tenant root. Real proposals almost always land inside a workspace or project underneath it, so this panel reads a structural, near-permanent "0 pending" — a false all-clear on the one page meant to catch it. The fix aggregates pending counts across every container you own (workspaces and projects, any depth) into one queue, each row jumping straight to that container's own suggestions list — including containers like Ops / Archive that aren't even in the top-level sidebar. The total also surfaces as a badge on the section label itself, so it's visible without opening the panel.
